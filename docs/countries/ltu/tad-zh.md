# 立陶宛（LTU）数据源说明——tad（议会法规数据库 TAD）

> 数据快照日期：2026-09-15。文中状态码、字节规模与日期字段均为当日对源站直连实测的真实值（可重放复核）；账本内计数在首次真实运行后补记（§5 末行）。
> 阅读前提：了解 `python cli.py` 用法即可，不需要读代码。立陶宛全部源总览见 [overview-zh.md](./overview-zh.md)。

## 1. 源概览

### 1.1 制度背景：立陶宛的官方公布媒介与 TAD 是什么

立陶宛的官方公布制度在 **2014 年换了载体**：政府公报《Valstybės žinios》（"国家新闻"，1990 年恢复独立后至 2013 年的法定公报）末刊为 **2013-12-31**；自 **2014-01-01** 起，一切法规的官方公布媒介改为 **Teisės aktų registras**（TAR，法规登记系统，门户 e-tar.lt，司法部主管）——《Teisėkūros pagrindų įstatymas》（立法基础法）同年生效。这一接替关系有两个相互独立的证据链：公开报道与议会公告（多源一致）；以及本源数据自身——2013 年前的文档记录公布于 `Valstybės žinios, 2001-06-20, Nr. 52-1816` 这样的期号，2014 年后的文档记录公布于 `TAR, 2024-06-14, Nr. 10906` 并带 TAR 登记号（2026-09-15 实测两例）。

**TAR 门户（e-tar.lt）不能作为机器采集通道**：整站置于 Cloudflare 浏览器校验之后（"Just a moment..." 页，2026-09-15 curl 实测 403），程序化 HTTP 客户端无法通过；TAR 另有面向注册用户的合同制数据服务（"Duomenų teikimas iš TAR"），需要签订数据提供协议，不是免密钥通道。开放数据门户 data.gov.lt 的接口 2026-09-15 实测返回服务器错误且站点防火墙拦截程序化访问，同样不可用。

**本源实际走的是议会一侧的镜像库。** 议会（Seimas）长期维护着自己的文档系统：老检索接口（www.lrs.lt 的 `/pls/inter3/` 服务，Oracle 数据库直出网页）、新门户 e-seimas.lrs.lt，以及其中的法规文档库 **TAD**（*Teisės aktų duomenų bazė*，法规数据库——响应地址里的 `TAD` 命名空间即此）。TAD 收录 2014 年前后**全部国家层级**法规文档，每份带完整公布引用（2014 前公报期号 / 2014 后 TAR 期号与登记号）、采纳日、生效日、全文与 Eurovoc 主题词。三层端点全部免密钥、免会话、免浏览器，且**全程无状态 GET**（2026-09-15 连续数十请求实测）。

**收录范围（838 个发布机构，2026-09-15 表单实测）**：议会（Seimas）、政府（Vyriausybė）、总统（Prezidentas）、全部部委（含历史沿革中的机构）。本源默认采集**四个规范层**：

| 默认切片 | 发布者 | 原生类型（Rūšis） | 内容 |
|---|---|---|---|
| `laws` | 议会 | Įstatymas（法律）、Kodeksas（法典）、Konstitucija（宪法）、Konstitucinis įstatymas（宪法法律）、Konstitucinis aktas（宪法文件） | 立法层全部成品 |
| `decrees` | 总统 | Dekretas（总统令） | 总统令 |
| `resolutions` | 政府 | Nutarimas（决议） | 政府决议 |
| `orders` | 各部委及中央机构（不限发布者） | Įsakymas（部令） | 部委令层：2024-06 单月全机构 474 条（2026-09-15 实测），类型过滤干净（单类型码 37，页内行全部为 Įsakymas） |

部委令一个类型码即可干净过滤（早期"过滤不可靠"的判断系三日小窗误判，2026-09-15 复查更正）。地方自治体规章、判例不在本源（TAD 本就不含）。

**文档形状**：每份文档在库内有两种标识——数字 `p_id`（老接口的文档主键，全库连续）与 `tadId`（新门户地址标识；2014 前后老文档 = `TAIS.<p_id>` 可由 p_id 推导，新文档 = 32 位十六进制串不可推导）。文档文本另有**原始版**（as-adopted，通过时的文本）与**汇总版**（suvestinė redakcija，修订后编纂文本，多数法律有多个版本日期）之分；本源采集**原始版**——它是"某天出台了什么"的定格证据，与公报公布口径一致。汇总版通道存在（2026-09-15 实测），见 §9"暂未用"清单。

### 1.2 与欧盟法的关系

1. **转化立法——在本源内，正常逐条抓取。** 立陶宛把 EU 指令转化为国内法用的是普通 įstatymas / Nutarimas，与本国产出同通道，按普通条目处理。
2. **直接生效的 EU 条例——不在本源。** 需要 EU 条例原文须去《欧盟官方公报》，超出本源范围。
3. **ES 关联字段随源照收。** 详情页的 "Ryšys su ES teisės aktais"（与 EU 法的关联，如 `Direktyva Nr. 2009/110, Celex Nr. 32009L0110`）原样入 meta（2026-09-15 实测样本 XI-1868 电子货币法即带此字段）——做 EU 影响研究时的现成素材。

## 2. 访问准备

| 项 | 说明 |
|---|---|
| API key | **不需要**，`.env` 无需任何条目 |
| 会话 | 无（全部端点无状态 GET；翻页参数 `p_no` 不依赖任何会话键，2026-09-15 实测） |
| 字符编码 | **两代并存**：老接口（枚举层）响应为 windows-1257 编码，新门户与 `/rs/` 文本服务为 UTF-8——解析按字节先试 UTF-8、失败回退 windows-1257，对调用方透明 |
| 限额 | 无公开限额。2026-09-15 连续数十请求零拦截；框架统一限速（0.5–1 秒/请求）足够安全 |
| 反爬 | lrs.lt 系全部无 Cloudflare 类防护，curl 直连即可（e-tar.lt 整站有，本源不走） |
| 响应格式 | 枚举层 HTML 表格（结构化 class 标注）；详情与文本为 HTML；无官方 JSON/XML |
| 空窗口行为 | 日期窗无结果 = HTTP 200 + 总数 `Iš viso - 0`（干净空，非故障） |

## 3. 抓什么：任务类型清单

每种任务 = 一次下载 + 一次解析。共 **3 种**：

| 任务类型 | 请求什么 | 产出什么 |
|---|---|---|
| `tad_list`（种子，逐日 × 逐切片一个） | GET 老接口检索 `rezult_l`（日期窗 + 机构 + 类型码，§1.1 切片表解出） | 解析结果行 → 每行一个 `tad_doc`；总数超过一页（每页 30 条）→ 按无状态翻页参数补种后续页；本片当日 0 条 → 合法空产出；**完整消费（有果无果一律）推进游标 `tad_last_date`**（账本里"已完整消费到哪一天"的进度标记，§7） |
| `tad_doc`（每文档一个） | GET 详情 `showdoc_l?p_id=<pid>`（服务端跳转到新门户文档页，自动跟随） | 一个文档记录入账（书目字段全部来自详情页，§4）+ 一个 `tad_text` 种子（携带从页面提取的 `tadId` 与公布日期）；公布字段缺失或形状异常 → 按故障升级，不静默吞掉 |
| `tad_text`（每文档一个） | GET 文本服务 `/rs/legalact/TAD/<tadId>/` | 响应字节原样落盘为文档主文件 `text.html`，框架把它挂回文档账（路径 / 字节校验和 / 格式 / 采集时间） |

任务链：`tad_list × (每一天 × 每个启用切片) → tad_doc × 每行 → tad_text × 每文档`。

命令行参数（key=value 形式）：

```
window=FROM:TO    闭区间日期窗口，如 2024-06-01:2024-06-03（必填，或改用 sync=1）
sync=1            增量：起点 = 游标 tad_last_date 次日，终点 = 昨天
scope=laws,decrees,resolutions,orders
                  启用哪些切片，逗号分隔（默认四层全开；如只要法律层 → scope=laws）
```

**窗口按"公布日期"还是"采纳日期"？** 老接口的日期窗匹配的是文档**采纳日期**（Priėmimo data 列）。这与发现通道的完整性有关：任何文档必然有采纳日，按采纳日枚举不漏；而公布日通常晚 1–14 天（2026-09-15 实测样本：采纳 2024-06-05 → TAR 公布 2024-06-14；2001 样本：采纳 2004-06-05 → 公报 2001-06-20）。账本里的 `publication_date` 仍记录**公布日**（研究时间轴主日期，§4）——**抓取时间轴 ≠ 数据时间轴**，入口设计只回答"发现全不全"。

## 4. 数据落到哪

**零领域表**（扁平文档型路径，同德国 BGBl / 西班牙 BOE）：本源采集单元是公布事件（原始文本一次定格），一个文档 = documents 一行；文档间的修订关系字段（如列表行的 `PAKEISTAS`——"已被修订"标记）是**字段**不是实体，随源照收进 meta（建图留给分析阶段）。汇总版（版本序列素材）本期不抓（§9）。

一切研究字段进 `documents` 一张表：

| 列 | 内容 |
|---|---|
| `doc_id` | `LTU_{公布日YYYYMMDD}_{hash8(source_url)}` |
| `title` | 完整题名（如 `Dėl valstybinės miško žemės pavertimo kitomis naudmenomis žemės sklypuose Šalčininkų rajono savivaldybėje`） |
| `publication_date` | **公布日**（Paskelbta）——2014 后为 TAR 公布日，2014 前为公报《Valstybės žinios》刊出日；研究时间轴的主日期 |
| `issuing_authority` | 通过机关全名（Priėmė，如 `Lietuvos Respublikos Vyriausybė`） |
| `source_url` | `https://www.lrs.lt/pls/inter3/dokpaieska.showdoc_l?p_id={pid}`——老接口文档正门，新旧文档通用、无一次性参数、完全可重建（tadId 对新文档不可推导，故不作 source_url 基底；新门户链接仍入 meta 备查） |
| `raw_format` / `language` | `html` / `lit`（立陶宛语；官方英文译文版不设通道，见 §8） |
| `doc_type` | 由 Rūšis 映射的受控类型（下表）；立陶宛语原词永存 meta |
| `entity_ref` | NULL（扁平国家） |
| `meta` | 见下 |

**meta 字段**（原生字段无损收，全字符串）：`pid`（老接口主键）、`tad_id`（`TAIS.138312` 或 32 位十六进制）、`tad_url`（新门户规范链接）、`native_type`（Rūšis 原词）、`dokumento_nr`（文号，如 `IX-357` / `473`）、**`priemimo_data`（采纳日）**、**`isigalioja`（生效日）**（与 publication_date 合成日期三件套，§5.3 时间序列底线）、`registravimo_duomenys`（TAR 登记串，如 `2024-06-14 Nr. 2024-10906`；2014 前文档为旧登记串如 `Nr. 1011010ISTA00IX-357`）、`paskelbta_leidinys`（公布媒介：`TAR` / `Valstybės žinios`）、`paskelbta_nr`（公布期号，如 `52-1816`）、`galiojanti_suvestine`（现行汇总版日期——**采集时点快照**，会随源站维护变化）、`eurovoc`（主题词，分号连接）、`es_rysys`（EU 法关联原文）、`status_annotations`（效力标注：`PAKEISTAS` / `Negalioja de jure`（法律上失效）等，分号连接，时点快照）、`scope_slice`（来自哪个采集切片）。

**doc_type 映射**（原生优先：Rūšis 原词永存 meta，映射只是一层受控别名；跨国可比的统一类型学不在采集层做）：

| Rūšis（立陶宛语原词） | 类型码 | doc_type |
|---|---|---|
| Konstitucija | 8 | CONSTITUTION |
| Įstatymas / Kodeksas / Konstitucinis įstatymas / Konstitucinis aktas | 1 / 10 / 173 / 250 | STATUTE |
| Dekretas | 29 | DECREE |
| Nutarimas | 31 | DECREE（政府决议≈行政法令层，原词照存） |
| Įsakymas | 37 | ORDER |
| 其余（Išvada 结论书等非默认切片） | — | OTHER |

文件落点（"一项政策一个文件夹"，年/日双层分片）：

```
{data_root}/LTU_policy/
├── state.db
├── failures/
└── 01_raw/tad/
    └── 2024/D20240614/                        ← 年 = 公布年；日 = 公布日
        └── 1815466/                           ← 一份文档一个文件夹（p_id 命名）
            └── text.html                      ← /rs/ 原始文本响应原样字节（文档主文件）
```

- `text.html` 是文档主文件（唯一挂 doc_id 的文件，账本 local_path 指向它）；元数据不落单独文件，全部在账本 meta。
- v1 每文件夹单文件；附件（Priedai）不抓（§8）。

## 5. 完整案例走查（2024-06-01..03 三日窗口实跑，源站直连实值）

一个真实窗口的全链数据（每步可重放，账本内计数可从 state.db 复查）：

1. **枚举**：3 天 × 8 个切片（5 个法律类类型码 + 总统令 + 政府决议 + 部委令）= 24 个枚举任务。6-01（周六）与 6-02（周日）全部 16 个切片为干净空窗（`Iš viso - 0`，记合法空产出、游标照推）；6-03（周一）政府决议切片命中 3 条、部委令切片命中 18 条，列表行自带标题、采纳日、文号、类型、生效日与 TAR 登记号。
2. **详情**：每条一个 `tad_doc` 任务（如 `GET …/showdoc_l?p_id=1811636`，服务端跳转到 TAD 页）。以政府提交议会法律草案的决议为例：类型 Nutarimas → doc_type `DECREE`；通过机关 `Lietuvos Respublikos Vyriausybė`；采纳日 2024-06-03、公布日 2024-06-03（媒介 TAR，登记号 `Nr. 2024-09979`）、生效日 2024-06-03（三日期齐全）；TAD 标识 `ca1c9b40219911efb121d2fe3a0eff27`（32 位十六进制，从页面提取）；Eurovoc 主题词随 meta 入账。部令同形状（如经济与创新部部长令，采纳/公布 2024-06-28、TAR Nr. 12073，2026-09-15 直连样本）。
3. **文本**：`GET …/rs/legalact/TAD/<tadId>/` → 原始版全文 HTML 字节原样落盘。21 份文件 5 KB–218 KB 不等。
4. **窗口合计**（库内实值，2026-09-15 实跑）：**66 任务全部 done（24 枚举 + 21 详情 + 21 文本），0 永久失败、0 升级；21 文档、21 文件、游标 `tad_last_date=2024-06-03`**。文件树 `01_raw/tad/2024/` 下按公布日分文件夹（`D20240603/` 等——部令中存在采纳 6-03、公布拖到 7 月初的个案，公布日轴落各自的文件夹）。
5. **三方对账**（2026-09-15 核对）：① 磁盘 sha256 ≡ 账本 file_hash，21/21 一致；② 源站 `/rs/` 复取字节 ≡ 磁盘，20/21 逐字节一致——1 份例外是源站对该文档内邮箱做的 Cloudflare 混淆（每请求变密钥、密文不同但解码后同一组邮箱，见 §8）；③ 源站独立复走 24 个切片的枚举，命中 p_id 多重集 ≡ 账本文档（21 ≡ 21）。
6. **幂等重跑**：同窗口再次运行 → 入队 0、执行 0、零网络请求（任务确定性跳过）。
7. **2014 年前的样子**（2001-06-05 法律 IX-357，2026-09-15 直连样本，未在本窗口内）：公布媒介字段 = `Valstybės žinios, 2001-06-20, Nr. 52-1816`，TAD 标识 = `TAIS.138312`（可由 p_id 推导），文本服务对老标识同样直接可用，正文含公报引用 `(Žin., 1996, Nr. 32-787)`；部令层老年代同样在库（2010-06 司法部 7 条部令实测）。

## 6. 怎么跑

```bash
# 演练（不入队执行，看会抓什么）
python cli.py collect --country ltu --source tad window=2024-06-01:2024-06-03 --dry-run

# 小窗口真实抓取（§5 的三日窗口）
python cli.py collect --country ltu --source tad window=2024-06-01:2024-06-03

# 每日增量（从上次游标的次日追到昨天）
python cli.py collect --country ltu --source tad sync=1

# 只收法律层（其余切片留待以后，改口径自动补抓、无需清库）
python cli.py collect --country ltu --source tad window=2024-06-01:2024-06-03 scope=laws

# 状态 / 快照 / 修复
python cli.py status --country ltu --source tad
python cli.py export --country ltu
python cli.py requeue --country ltu
```

## 7. 更新与增量

- **游标**：`tad_last_date`。每个 `tad_list` 完整消费**自己那一天的那个切片**就把游标推到该日——200 且解析完成（有果无果一律）都算完整消费；中途崩溃该日不推，下次自愈。同一天多个切片各自推进同一天的游标值（重复写同值无害；切片完成顺序颠倒只会让游标短暂回退，重扫被任务确定性去重，只多花枚举请求、不影响正确性）。
- **sync 终点取昨天、不取今天**：当日文档在源站录入需要时间（采纳与入库之间常见数天滞留，2024 样本采纳 06-05 → 入库 06-14）。"尚未录入"与"当日确无"在接口上同形（`Iš viso - 0`），为杜绝把前者误判为后者，增量默认只到昨天；且因为日期窗匹配**采纳日**（§3），增量天然会多覆盖一个滞留缓冲。
- **抓的是快照，不设重开**：原始文本与书目字段一次定格，同窗口重复运行安全（任务确定性去重，已抓直接跳过、零请求）。详情页的现行汇总版日期与效力标注是活视图，记录抓取当日状态；跟踪修订需按新窗口重扫（机制与既有枚举源一致，本源暂未设周期任务）。
- 往更早日期回填会把游标往回带，下次 sync 幂等重扫（无害，与既有判例一致）。库的覆盖从 1990 年恢复独立起连续（2001 窗口实测在库；更早 LTSR 时期文档在库但属另一法律体系，未纳入默认切片）。

## 8. 已知边界与缺口

| 缺口 | 说明 |
|---|---|
| **TAR 本体（e-tar.lt）不可达** | 整站 Cloudflare 浏览器校验（2026-09-15 实测）；TAR 合同制数据服务需签约。本源以议会镜像库替代（含部委令层），文档带 TAR 登记号可对账 |
| **汇总版（版本序列）不抓** | 通道已探明（新门户版本列表页 + `/rs/actualedition/` 文本端点，2026-09-15 实测）；原始版一次定格不含后续修订文本。版本序列研究另立源时启用 |
| **附件（Priedai）不抓** | 带附件的文档只收正文本体；附件清单未采集 |
| **官方译文版不设通道** | 文档库含英文译文（如 XI-1868 电子货币法，Kalba: Anglų，2026-09-15 实测）；默认枚举命中的是立陶宛语版，译文版未单独收录 |
| **个别文档含变动字节** | 源站对个别文档正文里的邮箱做 Cloudflare 混淆（每请求换密钥，密文不同、解码后同一邮箱且密钥在串内可自解，2026-09-15 实测 21 份中 1 份）——跨下载字节比对仅对该类文档失效；file\_hash 语义是落盘字节校验和 |
| **生效状态是时点快照** | `PAKEISTAS`、现行汇总版日期等抓的是当天值，不自动更新（§7） |
| **超长标题源站截断** | 标题字段源站按 1,000 字符截断（2026-09-15 实测一例：一份同时修订八部法律的政府决议）——原样入库不推断；全文在 `text.html` 内无损 |
| **枚举日期轴 = 采纳日** | 窗口按采纳日匹配（§3 的理由）；公布日滞后常见 1–14 天（实测个案采纳 6-03、公布 7-01），研究按公布日查询时窗口要相应外扩 |
| ** tadId 形状两代并存** | 老文档可推导（TAIS.<p_id>）、新文档不可推导（32 位十六进制，只能从详情页提取）——这也是 source_url 选老接口正门的原因（§4） |
| **字符编码两代并存** | 枚举层 windows-1257、门户与文本服务 UTF-8；解析器已内置回退，调用方无感（§2） |
| **部委令层体量** | Įsakymas 单月全机构约 474 条（2024-06 实测）——日常增量约 16 条/工作日（约 50 请求/天）无压力；全量回填的体量在回填立项时单独估算 |
