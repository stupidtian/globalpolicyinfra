> 数据快照日期：2026-09-07。文中期号、字节数与状态码均为当日对源站直连实测的真实值（可重放复核）；账本内计数在首次真实采集后补记（§5 末行）。
> 阅读前提：了解 `python cli.py` 用法即可，不需要读代码。日本全部源总览见 [overview-zh.md](./overview-zh.md)。

## 1. 源概览

### 1.1 制度背景：官報是什么、装了谁的产出

**官報**（かんぽう，日本国家官方公报，1883 年创刊）是日本**中央层级规范文件的法定公布媒介**——法律、政令等只有在此公布才产生法律效力。运营门户是**官報発行サイト**（www.kanpo.go.jp），由内阁府与独立行政法人国立印刷局发行。对政策研究而言，官報 = "日本中央政府每天出台了什么"的权威流水账。

官報按**期**出版，每天 1–4 期，期型四种（URL 代字用于编址，见 §1.3）：

| 期型 | 代字 | 装什么 | 本源是否采集 |
|---|---|---|---|
| **本紙**（ほんし，正刊） | `h` | 省令、告示、训令等法令类 + 国会事项、人事变动、官庁报告、公告 | **是（默认）** |
| **号外**（ごうがい，增刊） | `g` | **法律与政令在此颁布**（只在号外刊出）+ 省令、告示等 | **是（默认）** |
| 特別号外 | `t` | 不定期重要事项（如国事行为委任，2026-09-02 第 48 号实测） | **是（默认）** |
| 政府調達 | `c` | 政府采购招标公告（2016-04-01 起） | 否（非政策文件；参数可扩） |

**一个容易误解的分工（2026-06-19 双日核对实证）**：法律和政令只刊在号外，但省令、告示在**本紙与号外都会出现**（同日本紙与号外各载一部分）——因此本紙+号外+特別号外三期都收，序列才完整。2026-06-19 一日：本紙第 1730 号载省令 2 条等，号外第 135 号载法律（含《産業技術力強化法の一部を改正する法律（四一）》等）、政令、省令若干。

**不在本源里的东西**：国会立法过程（衆議院/参議院的法案审议——那是国会两院自己的系统）；现行法令的汇编文本（同一部法律当前有效版本的合并文本——在 e-Gov 法令検索，机器通道已确认存在，见 §8）。

### 1.2 出版节奏

- **工作日每天 8:30（东京时间）发行**；周末与节假日无刊（2026-09-05/06 双 404 实测）；每天发行本紙+号外+政府調達三期是常态。
- **特別号外**可在当日午后临时发行（2026-08-19 13:35、2026-08-21 13:40 实测）。
- **一日多期号外是常态**（2026 年 5 月 31 个发行日共 42 个号外实测）。
- 期号按年连续：本紙全年连续编号（2026-09-04 = 第 1783 号）、号外每年从第 1 号重计（2026-09-04 = 第 198 号）。

### 1.3 数据通道：静态目录页 + PDF 直链（免 key、无会话、无浏览器）

官報発行サイト是**纯静态 HTML 目录 + 直链 PDF**，没有 API、没有站内检索（官方 FAQ 明言）、没有 sitemap——但**日期编址全部可构造**，这比 API 更稳定：

| 对象 | URL 规则（2026-09-07 实测） |
|---|---|
| 日整期目录页（每天一个，列当日全部期型全部条目） | `https://www.kanpo.go.jp/{YYYYMMDD}/{YYYYMMDD}.fullcontents.html` |
| 期目录页 | `https://www.kanpo.go.jp/{YYYYMMDD}/{YYYYMMDD}{代字}{序号5位}/{YYYYMMDD}{代字}{序号}0000f.html` |
| 条目页（PDF 阅读器壳，约 2.7KB） | `{期目录}/{YYYYMMDD}{代字}{序号}00NNf.html`（NNN = 该条目起始页码） |
| **条目 PDF（正文所在）** | `{期目录}/pdf/{YYYYMMDD}{代字}{序号}00NN.pdf`——**由条目页文件名去掉 `f.html`、加 `pdf/` 前缀直接构造**，无需逐条请求条目页 |
| 月归档页（早期档案的枚举入口） | `https://www.kanpo.go.jp/old/{YYYYMM}.html` |
| 发行时刻表（近 90 天哪天出了哪几期） | `https://www.kanpo.go.jp/issueDateTime.html` |

日整期目录页的 HTML 结构：日期下按期分组（`本紙　第1780号` 等），期内按节（省令、法規的告示……）分组，每条目一行"标题 + 起始页码"，条目链接直指条目页。**日整期目录页始于 2024-01-01**（2023-12-01 实测 404）；更早的日期用月归档页枚举期目录页（两者内部结构同构，2026-09-04 本紙期目录与日页逐条核对一致：18 条同节同序）。

**条目没有自己的编号**：官報的编址单位是"某期第几页"，**多个条目常共享同一页 PDF**（2026-09-04 号外第 2 页载 4 个政令（二六九）～（二七二）实测）。本源用"URL 加条目序号"解决唯一性（§4）。

### 1.4 档案保留口径——决定能抓到什么年代什么内容的官方规则

站点对历史官報实行两段式保留（官方《公開対象の記事について》说明文件 + 2026-09-07 实测双确认）：

| 时期 | 在线内容 |
|---|---|
| 2003-07-15 ～ 2025-03-31 | **只有"法令等"**——法律、政令、条約、最高裁判所规则、府令/省令/庁令、规则、训令（+ 政府調達 2016-04-01 起）。公告、人事、告示等**从未进入在线档案**。实测表现：早期档案的期目录页里这些条目只剩无链接的纯文本行 |
| 2025-04-01 起 | 全部内容在线。但**涉及隐私的条目只保留 90 天**（裁判公示、帰化告示、破产公告、惩戒处分等官方清单类目；实测 2026-06-10 的 90 天期档案比当日新档少 5 条此类条目）；**号外国会会议录整期只保留 90 天**（过期后由国立国会图书馆的系统接替） |

由此，**"法令等"节在 2003-07-15 至今全时段可得且口径一致**——这是本源默认口径的依据（§3）。更早的年代见 §8 缺口表。

### 1.5 与 e-Gov 法令検索的关系

e-Gov 法令検索（laws.e-gov.go.jp，总务省行政管理局运营）是**现行法令汇编库**：全部施行中法令（2026-09-07 实测列表 8,995 部，最早到 1872 年公布的法令）的**标准 XML 全文**，免 key 机器通道（API + 全量打包下载）。它与官報互补而不重叠：e-Gov 给"这部法现在长什么样"，官報给"颁布事件 + 颁布时原样文本"；e-Gov 没有颁布时间序列、没有历史版本、告示等公报内容也大部不在其库中。本源（官報）承担时间序列主体；e-Gov 通道已验明、留作后续扩展（§8）。

## 2. 访问准备

| 项 | 说明 |
|---|---|
| API key | **不需要**，`.env` 无需任何条目 |
| 会话 | 无（无 cookie、无 token，全部请求无状态直连） |
| 请求头 | 传输层自带自报身份的 User-Agent（学术研究爬虫 + 本项目开源仓库地址）。**不建议**伪装浏览器 UA：站点 robots.txt 对通用网络爬虫关闭了日期目录，但内容按官方公共数据利用规约开放复用，诚实身份 + 慢速是与之相称的姿态 |
| 限速 | 框架统一 1–2 秒/请求（`--delay 1:2`）。本源体积小：每日增量约 3–5 个请求 |
| robots.txt | `User-agent: *` 禁 `/20*` 与 `/old/`（日期目录）；对 `ndl-japan`（国立国会图书馆）全放行。结合内容开放许可，判断其意图是服务器负载治理而非内容限制——本源以自报身份 + 低速 + 小量运行 |
| 响应格式 | 目录页/条目页 HTML，**UTF-8**（2003 年与 2026 年页面均实测）；条目正文 **PDF 1.4** |
| PDF 文本层 | **真实文本层存在（非扫描）**，但使用自定义 CID 字体编码：pdfminer.six 可正确抽取日文文本，pypdf 抽出乱码；版面为纵向排版，逐字提取时断行严重——正文文本化属于清洗阶段的工序，采集层只落盘原样 PDF |
| 许可 | **公共データ利用規約（第 1.0 版，PDL1.0）**：允许商用与非商用再利用；须注明出处——官方示例 `出典：官報発行サイト（该页 URL）`；编辑加工后须注明已加工，且不得呈现为官報原载样式。个别内容（如部分公告）有个别法令的利用限制 |

## 3. 抓什么：任务类型清单

每种任务 = 一次下载 + 一次解析。共 **4 种**：

| 任务类型 | 请求什么 | 产出什么 |
|---|---|---|
| `kanpo_day`（种子，每发行日一个） | GET 日整期目录页（地址按日期构造；90 天内走根级地址、更早走 `/old/` 永久地址，由种子生成按日龄分配） | 解析当日各期条目 → 按口径过滤（默认期型 `h,g,t` × 法令等节）→ 每条目生成一个 `kanpo_doc`；当日无刊（周末/节假日，返回 404 且响应体为已知 404 页）→ 记"合法空"并推进游标 |
| `kanpo_month`（种子，每月一个） | GET 月归档页 `/old/{YYYYMM}.html`（2003-07-15～2023-12-31 的历史档案用；2024-01-01 起有日整期目录页，不需要月页） | 解析当月各发行日的期目录链接 → 每期一个 `kanpo_issue` |
| `kanpo_issue` | GET 期目录页 | 解析该期条目（**只取有链接的条目**——早期档案中被保留规则排除的条目呈现为无链接文本，跳过并计数）→ 每条目一个 `kanpo_doc` |
| `kanpo_doc` | GET 条目 PDF（地址由条目页地址直接构造，§1.3） | 一个文档记录 + PDF 原样落盘 |

任务链：`kanpo_day × 每个发行日 → kanpo_doc × 每条目标条目`（2024-01-01 起）；`kanpo_month × 每月 → kanpo_issue × 每期 → kanpo_doc`（更早档案）。

命令行参数（key=value 形式）：

```
window=FROM:TO    闭区间日期窗口，如 2026-09-01:2026-09-06（必填，或改用 sync=1）
sync=1            增量：起点 = 游标 kanpo_last_date 次日，终点 = 昨天（官報每天 8:30 东京时间发行，
                  特別号外可当日午后补发——"昨天"终点确保当天内容已定型）
months=FROM:TO    历史档案回填入口（如 months=2023-07:2023-12），走月页+期目录路径
types=h,g,t       采集哪些期型（默认本紙+号外+特別号外；如 h,g,t,c 连政府調達一起收）
sections=law      采集哪些节（默认 law = 法令等节集；如 law,告示 扩收告示——注意 2025-04-01 之前的
                  档案不含告示，见 §1.4）
```

**默认口径 = 法令等节**（法律、政令、条約、最高裁判所规则、府令、省令、庁令、内阁官房令、内阁府令、デジタル庁令、规则、训令）：这是 2003-07-15 以来全时段可得且口径一致的节集合。日常一天的量级：采样五日（2026-08-28～09-04）为 0～13 条、约 5 条均值。

## 4. 数据落到哪

**零领域表**（扁平文档型，同德国 BGBl / 法国 JORF / 西班牙 BOE 判例）：公报刊出即定、条目即文档本体，语料中没有跨文档的持久实体。一切研究字段进 `documents` 一张表：

| 列 | 内容 |
|---|---|
| `doc_id` | `JPN_{刊出日YYYYMMDD}_{hash8(source_url)}` |
| `title` | 条目标题原样（含番号括号，如 `地域公共交通の活性化及び再生に関する法律の一部を改正する法律の施行期日を定める政令（二六九）`） |
| `publication_date` | 官報刊出日——研究时间轴的主日期 |
| `issuing_authority` | 留空（标题番号括号内的府省**简称**如"法務""農林水産"不展开为全称，原文无损保存在 meta.notice_no；无判据不猜） |
| `source_url` | **永久档案地址 + 条目序号片段**：`https://www.kanpo.go.jp/old/{日期}/{期代号}/{条目页名}f.html#e{序号}`（理由见下） |
| `raw_format` / `language` | `pdf` / `jpn` |
| `doc_type` | 由节名映射的受控类型（下表）；日语节名原词永存 meta |
| `entity_ref` | NULL（扁平国家） |
| `meta` | 见下 |

**source_url 为什么长这样**（本源两个特殊设计）：

1. **同一文档有两个地址**：发布后 90 天内挂根级（`/{日期}/…`），之后只挂永久档案（`/old/{日期}/…`），两地址内容字节相同（2026-06-10 页 PDF 双地址实测：均 143,139 字节、sha256 相同）。账本统一记 `/old/` 永久形，同一文档跨 90 天重抓才不会算成两份。**注意**：`/old/` 地址在文档发布后约 90 天内暂不解析（站点尚未迁入）——即新入库文档的 source_url 有 ≤90 天的"激活等待期"，之后永久有效（2003 年页面至今在线实测）。
2. **条目序号片段 `#e{序号}`**：多个条目共享同一页 PDF（§1.3），纯页面地址无法区分。序号 = 该条目在其期目录链接列表中的位次（刊出即定，重新解析目录可复现）。URL 的 `#` 片段不参与 HTTP 请求（带与不带片段实测返回字节相同），因此这个地址永远是官網该页阅读器的有效链接，片段纯粹是账本区分条目的记账后缀。

**doc_type 映射**（原生节名 → 受控类型；跨国的类型归并不在采集层做）：

| 原生节名（日语原词） | doc_type |
|---|---|
| 法律 | STATUTE |
| 政令 | DECREE |
| 省令 / 府令 / 庁令 / 内阁官房令 / 内阁府令 / デジタル庁令（含"府令・省令"复合节名，原文全存） | SECONDARY_LEGISLATION |
| 法規的告示 | REGULATION |
| 其余（规则、训令、条約、詔書、その他告示、公告、人事異動、官庁報告等） | OTHER（区别性信息已在标题番号括号内无损，如"最高裁""気象庁"） |

**meta 字段**（原生字段无损收，全字符串）：`date`（刊出日）、`issue_type`（本紙/号外/特別号外/政府調達）、`issue_code`（如 `g00135`）、`issue_no`（第 135 号）、`section_h2/h3/h4`（原生节路径）、`native_type`（条目所属一级节名）、`page`（起始页码）、`ordinal_in_issue`（期内条目序号）、`notice_no`（标题番号括号串原文，如 `法務四八`、`二六九`）、`ns_fetched`（实际抓取的地址域，备审计）。

文件落点（"一项政策一个文件夹"，年/日双层分片）：

```
{data_root}/JPN_policy/
├── state.db
├── failures/
└── 01_raw/kanpo/
    └── 2026/D20260619/                ← 年 = 刊出年；日 = 刊出日
        └── g00135/                     ← 期代号（g=号外第135号）
            └── 20260619g001350005e7/   ← 一条目一文件夹（页名 + 条目序号）
                └── 20260619g001350005.pdf  ← 条目 PDF 原样字节（源文件名零转写）
```

共享同一页 PDF 的多条目各自持有文件夹与 PDF 副本（磁盘代价接受，换取每条目自包含）。

## 5. 完整案例走查（2026-06-19 一条法律的全链，源站直连实值）

1. **日整期目录**：`GET /20260619/20260619.fullcontents.html` → 200。当日三期：本紙第 1730 号、号外第 135 号、政府調達第 112 号。号外含"法律"节，5 条法律条目（含《産業技術力強化法の一部を改正する法律（四一）》，起始页 5）。
2. **条目定位**：法律（四一）的条目页地址 `20260619g00135/20260619g001350005f.html`，期内条目序号 7 → 规范 source_url = `https://www.kanpo.go.jp/old/20260619/20260619g00135/20260619g001350005f.html#e7`。
3. **PDF 下载**：地址构造 `20260619g00135/pdf/20260619g001350005.pdf` → 200，132,596 字节，PDF 1.4，1 页，文本层可用 pdfminer.six 抽取（cid 字体，纵向排版）。
4. **入账落盘**：文件夹 `01_raw/kanpo/2026/D20260619/g00135/20260619g001350005e7/`；documents 一行（doc_id 以刊出日 2026-06-19 与规范 source_url 计算；doc_type=STATUTE；meta 含期型/节名/页码/序号/番号原文等）。
5. **同窗口形态覆盖**（2026-09-01:09-06 六日窗口）：09-01（周一，本紙载省令 2 + 号外载規則 3）、09-02（特別号外第 48 号当日，号外载省令 1）、09-03（周四，零法令日——空产出是合法形态）、09-04（号外第 2 页 4 个政令共享页案例 e1–e4）、09-05/06（周末双 404——无刊日游标照推）。
6. **账本内计数**（首次真实采集实值，2026-09-08）：
   - **六日窗口**：18 任务全 done（6 `kanpo_day` + 12 `kanpo_doc`）、0 失败 0 告警；12 文档 12 文件，游标推至 2026-09-06。构成（doc_type）：省令 SECONDARY_LEGISLATION 5（本紙 3 + 号外 2）、政令 DECREE 4（全部在 09-04 号外第 2 页共享页上，条目序号 e1–e4）、規則 OTHER 3（人事院規則等）。磁盘 ≡ 账本 12/12 哈希一致；抽 1 件与源站直连逐字节相同（114,688 字节）；同窗重跑零请求；`sync=1`（游标已到昨天）零种子零请求。

   - 两通道并跑后台账合计：124 文档、161 任务、游标 `kanpo_last_date=2026-09-07`。

## 6. 怎么跑

```bash
# 演练（不入队执行，看会抓什么）
python cli.py collect --country jpn --source kanpo window=2026-09-01:2026-09-06 --dry-run

# 小窗口真实抓取（§5 的六日窗口）
python cli.py collect --country jpn --source kanpo window=2026-09-01:2026-09-06 --delay 1:2
```

## 7. 更新与增量

- **游标**：`kanpo_last_date`。每个 `kanpo_day` 完整消费**自己那一天**才把游标推到该日——目录页解析完成（无论当日有无目标条目）、或 404 经响应体验证为已知无刊页，都算完整消费；中途崩溃该日不推，下次自愈。`kanpo_month`/`kanpo_issue`/`kanpo_doc` 不动游标：历史回填早于游标时不回拖水位线。
- **sync 终点取昨天**：当日官報 8:30（东京时间）发行、特別号外可午后补发；"今天"在日内状态下不定型，增量默认只追到昨天。
- **公报刊出即定，无重开机制**：同窗口重复运行安全（任务确定性去重，已抓直接跳过、零请求）。
- **90 天隐私窗口与默认口径无关**：默认的法令等节永久在线；只有扩收公告/官庁報告等节时，其中隐私类条目才有"发布后 90 天内必须抓到"的时限（§1.4）。
- 往更早日期回填（月页路径）不影响增量；两路任意交错。

## 8. 已知边界与缺口

| 缺口 | 说明 |
|---|---|
| **1953-01-01 ～ 2003-07-14 的官報** | 互联网无公开档案：国立国会图书馆数字馆藏的官報只到 1952-04-30，续刊不上网；仅国立印刷局的付费官報情報検索サービス（1947 年起、图书馆终端）与到馆可查，不适合批量采集 |
| **1883-07-02 ～ 1952-04-30 的官報** | 国立国会图书馆数字馆藏已数字化并互联网公开（约 1,000 册扫描图像，IIIF 图像接口可用，2026-09-07 实测）——图像源、独立工程，需要时另立源 |
| **2025-04-01 前档案只含法令等** | 告示、公告、人事等节在早期档案中不可得（§1.4）；`sections` 参数扩收时早期时段自然稀疏，序列在 2025-04-01 前后不等宽 |
| **隐私类条目 90 天下线** | 扩收非默认节时，隐私类目（破产公告、帰化告示等）发布 90 天后从站点撤除；号外国会会议录整期 90 天后撤除——扩口采集需保持至少季度级新鲜度 |
| **条目无原生编号** | 官報编址到页不到条目；多条目共享页 PDF（§4 的序号片段设计）。共享页 PDF 按条目复制落盘 |
| **source_url 激活等待期** | 永久档案地址在文档发布后约 90 天内暂不解析（§4）；期间根级地址可访问 |
| **无站内检索** | 官報発行サイト无关键词检索（官方 FAQ；国立印刷局另营付费检索服务）——本源以逐日枚举全覆盖，不依赖检索 |
| **PDF 文本抽取** | cid 字体 + 纵向排版：pdfminer.six 可正确抽取但断行碎（§2）；pypdf 不可用。文本化是清洗阶段工序 |
| **政府調達默认不收** | 采购公告非政策文件（2016-04-01 起）；`types` 参数可扩 |
| **现行法令汇编文本** | 不在本源（官報是颁布原样）。e-Gov 法令検索已验明免 key 通道：现行 8,995 部法令的标准 XML 全文（API `/api/1/lawdata/{id}` + 全量打包下载 + 2020-11-24 起每日更新流）——需要时另立源 |
| **法令的施行日不在目录层** | 施行日（何时生效）写在 PDF 正文中，目录页无此字段；采集层记刊出日，施行日留待清洗阶段从正文抽取 |
| 本紙/号外分工 | 法律与政令只在号外、省令告示两期都载（§1.1）——期型过滤时勿只收号外 |
