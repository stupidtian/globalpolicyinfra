# 韩国（KOR）数据源说明——lawgokr（国家法令信息中心现行法规）

> 文中数量为真实运行的实测参考值；你运行时的产出取决于所选页窗口。
> 阅读前提：了解仓库根目录 `python cli.py` 的用法即可，不需要读代码。

## 1. 源概览

### 1.1 制度背景：law.go.kr 与现行法规库

**국가법령정보센터**（[www.law.go.kr](https://www.law.go.kr)，법제처 运营）是韩国官方法令信息的一站式聚合门户。本源抓其**现行法规库（현행법령）**：当前有效的 헌법·법률·대통령령·총리령·부령·各宪法机关规则——官方 2026-08-12 口径共 **5,605 部**（立法系统 1,720 / 行政委任立法 3,503 / 其他宪法机关 383）。**一个名录同时覆盖立法与行政两个系统**，列表行以公布号前缀（법률/대통령령/○○부령 제N호）标识种类。名录默认包含已公布、尚未施行的版本（시행예정），全量约 **6,732 行**（135 页 × 50 + 尾页 32）。

站内还有其他语料，本源不抓（见第 8 节）：행정규칙（行政规则）约 149K 条、자치법규（地方法规）161K、판례·해석례（判例与解释）156K、별표서식（附表附件）4M、연혁법령（历史版本库）155K。

### 1.2 技术形态：JavaScript 界面，普通 HTTP 接口

网站的搜索界面是 JavaScript 动态渲染的，但底层数据接口是**普通 HTTP 查询**——列表、正文、修订理由、版本清单四类端点同时接受 GET 查询串与 POST 表单（实测返回逐字节一致），**无需浏览器**。翻页就是 `pg` 参数，任意页码一次请求即达。**无 cookie、无令牌、无 API key、无 TLS 指纹检查**。

**版本机制**（整个修订史抓取的基础）：一部法规的稳定身份是 `lsId`（修订不变）；每次修订产生一个**独立版本 seq**，每个版本有自己的施行日 `efYd`——(seq, efYd) 二元组唯一确定一个版本快照，正文接口对现行版与历史版**同样适用**。现行名录负责发现法规，版本时间线接口负责回溯该法规的全部历史版本。

## 2. 访问准备

| 项 | 说明 |
|---|---|
| API key | **不需要**，`.env` 零条目（姊妹站 open.law.go.kr 的官方 Open API 需申请 OC key，本源不用它） |
| 会话 | **不需要**——无 cookie 依赖、无 csrf 令牌 |
| 限额 | 无公开限额；连续抓取未遇拦截 |
| 限速 | 默认每请求间隔 0.5–1.0 秒 |
| 反爬 | 未发现（无验证码、无 UA 检查、无 TLS 指纹检查） |
| 响应格式 | 全部 UTF-8 HTML 片段（列表/正文/理由/版本清单）；另有 PDF 端点为二进制（本源未启用，见第 8 节） |
| 请求头 | `X-Requested-With: XMLHttpRequest` + 同源 `Referer` 需随请求发送；默认 UA 即可 |

## 3. 抓什么：任务类型清单（4 种）

**一部法规一条完整生命周期**：历史版本 → 现行版本 → 已公布未施行的未来版本，全部挂靠在同一部法规名下；名录里一部法规只占一行。

```
kor_list(pg=N) ──按法规去重──> 每部法规一个锚点版本 kor_body(seq, 最早施行日)
                                  ├─> laws 实体行（法规表，ls_id 为主键）
                                  ├─> kor_versions ──> 每个历史版本 kor_body + kor_reason
                                  └─> kor_reason(锚点版本的修订理由)
```

| 任务类型 | 请求什么 | 产出什么 |
|---|---|---|
| `kor_list`（种子） | 列表接口 `lsScListR.do`（`pg` 翻页） | **按法规去重**——同 seq 多行是同一次修法的分条施行视图（两行公布号相同），只取最早施行日作锚点，其余视图由版本时间线完整回收；每部法规生成一个 `kor_body`；`walk=1` 时页满 50 条自动续抓下一页（超出末页返回 200 + 0 条，自动停止） |
| `kor_body` | 正文接口 `lsInfoR.do` | 正文+元数据 → documents 一行（`entity_ref=laws:{lsId}` 挂靠到法规）+ HTML 落盘；**锚点正文**（名录发现的）另写 `laws` 实体行并派生 `kor_versions`；历史正文不反查时间线（时间线已在手）；极老的历史版本（如 1963 年）正文接口返回无内容的致歉页，任务记"预期为空"跳过 |
| `kor_versions` | 版本时间线 `lsHstListR.do`（**必须带 `lsId`**，缺失会落入空分支） | 一部法规的全部版本清单 → 为每个历史版本派生 `kor_body` + `kor_reason`；一部法规的时间线恰好请求一次 |
| `kor_reason` | 修订理由接口 `lsRvsDocInfoR.do` | 제정·개정이유（官方修订理由 + 修订条文，**每个版本一份**）→ documents 一行（挂靠同法规）+ 落盘 |

命令行参数（key=value）：

```
pages=1-2        必填，页区间："1"、"1-2"、"1,3" 或 "all"（all = 从第 1 页自动翻到末页）
max_laws=5       每页实际深抓的法规数上限（测试护栏；触顶则该页停止派生）
refresh=2026-08-31T13:00   增量重跑：ISO 时间戳，详见第 7 节
```

**增量语义**：已入库内容**永不重抓**（任务身份确定性去重）；新法规与新修订经 `refresh=更新的时间戳` 重走名录来发现——被修订的法规其锚点 seq 发生变化 → 新任务 → 新版本入库，`laws` 实体行随之更新，旧版本文档原地保留；未变化的法规全部命中"已完成即跳过"。实测：refresh 重跑只重读名录页，新增文档数为 0。

**法规种类映射**：按公布号前缀尾词映射 `doc_type`——…법률→`STATUTE`；…령（대통령령/총리령/○○부령/처령）→`DECREE`；…규칙（국회규칙/대법원규칙/헌법재판소규칙/선거관리위원회규칙/감사원규칙）→`RULE`；헌법→`CONSTITUTION`；其余→`OTHER`。韩语原词整段保留在 `meta.promulgation_type`。

## 4. 数据落到哪

**一张法规表 `laws` + documents 表 + 每个版本一个文件夹**：

| 位置 | 记什么 |
|---|---|
| `laws` 表 | 一部法规一行：`ls_id` 主键（修订不变的身份）、法规名、简称、主管部委、种类、当前锚点版本指针（`current_seq`/`current_ef_yd`，随增量更新） |
| `documents` 表 | 一个版本一份：正文与修订理由都是文档，`entity_ref='laws:{ls_id}'` 挂靠所属法规 |
| `01_raw/lawgokr/{seq 前两位}/{seq}_{efYd}/` | 该版本的全部材料（人读镜像，路径入账） |

documents 主要字段：

| 列 | 正文文档（kor_body） | 理由文档（kor_reason） |
|---|---|---|
| `title` | 法规名（去简称后缀） | 同法规名 + " — 제정·개정이유" |
| `publication_date` | 公布信息中的**公布日**（解析不到时回退施行日，meta 标记） | 同左 |
| `source_url` | `…/lsInfoP.do?lsiSeq={seq}&efYd={efYd}` | `…/lsRvsDocInfoR.do?lsiSeq={seq}&efYd={efYd}` |
| `doc_type` | 按上节种类映射 | `OTHER` |
| `meta` | `lsi_seq`、`ef_yd`、`ls_id`、`law_abbreviation`、`promulgation_type`（韩语原词）、`promulgation_no`、`amendment_type`（제정/일부개정/타법개정…）、`ministry`、`ministry_dept`、`ministry_phone`、`effective_date`、（回退时）`date_fallback` | `lsi_seq`、`ef_yd`、`ls_id`、`doc_kind=reason`、`promulgation_no`、`related_source_url` |

文件夹布局（真实示例，同一部法规的两个版本各占一个文件夹）：

```
01_raw/lawgokr/
├── 25/253527_20230808/               ← 现行版（2023 年修订）
│   ├── policy_253527_20230808.html   ← 正文
│   └── reason_253527_20230808.html   ← 修订理由
└── 86/86330_20080629/                ← 同一部法规的 2008 年制定版（独立版本 = 独立文件夹）
```

## 5. 完整案例走查：10·27법난법（从制定到现行的全程）

一部法规 8 个版本的完整修订史（真实数据实例）：

1. **名录发现**：名录第 1 页行 1 = seq 253527 / 施行日 20230808，title 含全部公布信息"[시행 2023. 8. 8.] [법률 제19592호, 2023. 8. 8., 타법개정]"；
2. **正文**：法规名"10ㆍ27법난 피해자의 명예회복 등에 관한 법률"（简称 10ㆍ27법난법）、主管部委 문화체육관광부（종무1담당관，044-203-2314）、`lsId=010719`、15 组条文、10 个附则头（正文尾部自嵌历次修订索引）、28,719 B 落盘；
3. **版本时间线**：返回 **8 个版本**——2008 年制定（법률 제8995호）→ 2010/2013（两次施行）/2016/2018/2021 → 2023 现行，每个版本有独立 seq（2008 年原始版 seq=86330）；
4. **历史版本**：2008 年制定版全文 26,514 B——公布头标注"제정"、附则只有 1 个、还包含后来被删除的 제4조。可见版本快照是真实的历史文本，不是同一份文档的复制；
5. **修订理由**：现行版理由 4,959 B（"법률용어 정비를 위한… 43개 법률 일부개정"官方修法说明 + 修订条文对照）；2008 年制定版同样有理由文档（4,710 B）。

这部法规最终入库：**8 份正文 + 8 份理由 = 16 行 documents，全部 `entity_ref='laws:010719'`**，`laws` 表一行。

## 6. 怎么跑

```bash
# 演练（不抓任何东西，看会入队什么）
python cli.py collect --country kor --source lawgokr pages=1 max_laws=5 --dry-run

# 小窗口全链（5 部法规的正文 + 全部历史版本 + 修订理由，约 100 次请求）
python cli.py collect --country kor --source lawgokr pages=1 max_laws=5

# 全量采集（名录 135 页 ≈ 6,700 部法规及其全部版本链，分批进行）
python cli.py collect --country kor --source lawgokr pages=all

# 增量重跑（只重读名录发现新法规/新修订，已入库内容零重抓）
python cli.py collect --country kor --source lawgokr pages=all refresh=2026-09-01T09:00

# 状态 / 快照 / 修复
python cli.py status --country kor --source lawgokr
python cli.py export --country kor
python cli.py requeue --country kor        # 失败任务复位
```

## 7. 更新与增量

- **重跑安全**：任务身份确定性去重——重复运行同一命令，已完成的部分直接跳过，近零成本；
- **增量 = refresh 重走名录**：`refresh=<比上次更新的 ISO 时间戳>` 让已完成的名录读取任务重开重读（每页请求一次），正文/理由任务不带信号 → 已完成即跳过。被修订的法规自动补抓新版本（新 seq = 新任务），`laws` 行的锚点指针随之更新；成本 ≈ 名录页数（全库 135 页）+ 真正新增的内容；
- **修订史的完整性**：每个现行法规都自动回溯全部历史版本，新旧版本自动成链；
- **发现边界**：**整体废止的法规不在现行名录里，本源无法发现它们**。研究"政策终止"需要历史版本库（연혁법령，15.5 万条）作发现层，属于后续扩展（见第 8 节）。

## 8. 已知边界与缺口

| 缺口 | 说明 |
|---|---|
| PDF 下载 | 可用但未启用（`lsPdfPrint.do`）：内容与 HTML 正文同源渲染，且**非字节稳定**（同大小不同哈希）；HTML 为准 |
| 极老的历史版本 | 1963 年等远古版本正文接口返回无内容的致歉页（HTTP 200），任务记"预期为空"跳过——数据在源站即不提供 |
| 整体废止的法规 | 不在现行名录，本源发现不了（见第 7 节）；需要历史版本库（연혁법령）语料，其列表参数尚未验证 |
| 越界页行为 | `pg` 超出末页返回 200 + 0 条（不是报错）——解析为"预期为空"，翻页链自动停止 |
| 名录菜单参数 | 列表接口查询串里的 `menuId/subMenuId` 服务端不识别，语料切换由表单参数驱动——将来扩围其他语料时需先验证参数 |
| 행정규칙（行政规则）语料 | 约 149K 条，端点已验证（列表 `admRulScListR.do` 需携带完整参数集、缺参 404；详情 `admRulInfoR.do`），如需采集可作为独立数据源接入 |
| 无理由文档的版本 | 个别版本可能没有 제정·개정문（响应中无标记）→ 任务记"预期为空"，不告警 |
| 抓取礼节 | 站点访问量很大（官方口径日 PV 2,160 万），默认 0.5–1.0 秒/请求的限速保持礼貌 |

## 9. 端点速查表

均位于 `https://www.law.go.kr/` 下（GET 与 POST 同效；需随带 `X-Requested-With: XMLHttpRequest` + 同源 Referer；全部 UTF-8）：

| 用途 | 端点与参数 |
|---|---|
| 现行法规列表（50/页） | `lsScListR.do?menuId=1&subMenuId=15&tabMenuId=81&q=*&outmax=50&p7=0&p19=1,3&pg={N}&fsort=10,41,21,31&lsType=null&section=lawNm&lsiSeq=0&p9=2,4` → 行 onclick `lsViewWideAll('seq','efYd',…)`，title 属性含全部公布信息 |
| 版本正文+元数据 | `lsInfoR.do?lsiSeq={seq}&efYd={efYd}&efYn=Y&nwJoYnInfo=Y&efGubun=Y&chrClsCd=010202&ancYnChk=0&netPrivateYn=N&vSct=*`（最小参数 `lsiSeq&efYd` 亦可）→ h2 标题 / `ct_sub` 公布信息 / `cont_subtit` 소관부처 / hidden `lsId` / `pgroup` 条文 / 부칙 |
| 版本时间线 | `lsHstListR.do`（正文参数 + **`lsId`**，缺失则返回空）→ 行 onclick `lsViewLsHst2('seq','公布日','公布号','施行日','N','0','修订类型')` |
| 制定·修订理由 | `lsRvsDocInfoR.do`（与正文同参数集；最小参数亦可）→ 【제정·개정이유】+【제정·개정문】，hidden 域 `lsNm/lsId/ancYd/ancNo` |
| 打印视图 | `lsInfoP.do?lsiSeq={seq}&efYd={efYd}`（GET；doc_id 的规范 URL 以它为基础） |
| PDF 下载（未启用） | `lsPdfPrint.do`（正文参数 + `docCls=pdf…`） |
| 条文级沿革（未启用） | `lsJoHstProc.do`（`lsId&lsiSeq&joSeq&chrClsCd`） |

**源里还有但暂未用的**（每项 = 将来可加一种任务类型）：법령체계도（法规体系图）、신구법비교/3단비교（新旧文对照）、별표·서식检索（HWP 附表附件 400 万）、조약·자치법규·판례 各语料、44 个政策领域/按部委浏览两个维度。
