# 印度（IND）数据源总览
> 一个源一个文件：本文件只做总览与共享信息，各源细节见对应文件。
> 文件命名规则：`{iso3}/{source}-{lang}.md`（国家文件夹 + 语言后缀，lang ∈ zh/en）。

## 1. 源清单

| 源 | 覆盖什么 | 数据从哪来 | 说明文件 |
|---|---|---|---|
| `gazette` | 印度联邦公报（Gazette of India）刊出的一切：法律、法令、条例、部委规则与法定命令等，一次刊登 = 一条数据 | [egazette.gov.in](https://egazette.gov.in)（电子公报门户，出版署/住房与城市事务部，NIC 托管） | [gazette-zh.md](./gazette-zh.md) |

公报是印度的法定公布媒介（《1897 年通用条款法》第 3(24) 条将"Official Gazette"定义为 Gazette of India，第 22 条规定规则未经公报公布不生效）。现行法编纂库 India Code（indiacode.gov.in，司法部立法司）是本国的另一官方来源，尚未收入本包。

## 1b. 三结构现状

- **时间序列（强制底线）**：由 `gazette` 承担——一次刊登 = 一行，原生发布日期（`dc.date` 类目的字段为公报行的 PublishDate/IssueDate 两列）+ 上传日期分列入账；条目编号（UGID）自带刊发日期。缺口见 §3。
- **决策过程**：记缺。公报 Part II Sec 2 载有法案一读文本与专委会报告（过程材料），当前未采集；议会过程第三方（PRS）不入采集。
- **版本序列**：记缺。India Code 载有修 正谱系（Act Amendments 集合 + 母法指针），其源接入后可补。

## 2. 共享访问准备

- **无需 API key**。门户为 ASP.NET WebForms 会话制，命令行采集需要：① 可达 egazette.gov.in 的网络路径（2026-10-04/15 实测自中国大陆网络直连不可达，需经标准 `HTTPS_PROXY` 环境变量走代理，框架传输层原生识别）；② **`REQUESTS_CA_BUNDLE` 指向含 Let's Encrypt 全部中间证书的 CA 包**——门户 TLS 配置只发叶证书不发中间证书（2026-10-16 实测签发者在 YR1/YR2 间轮换），Python 默认证书包验签失败；修法 = 从 [letsencrypt.org/certificates](https://letsencrypt.org/certificates/) 下载全部中间证书 PEM 与系统 CA 包合并后注入该环境变量。
- **礼貌限速**：`collect --delay 2:4`（秒）为推荐节奏；会话链源为单线程执行（引擎自动封顶 1 worker）。
- 数据目录：`{data_root}/IND_policy/`（首次运行自动创建）。

## 3. 尚未覆盖的政策层

| 层 | 现状 |
|---|---|
| 现行法编纂库 India Code（indiacode.gov.in） | 未接入。DSpace 9.1 开放 REST 接口，中央层 23 集合 58,179 条目（2026-10-04 实测），元数据含制定/生效/登记日期与修订指针，接入即可补版本序列 |
| 公报 Sec 3(ii)（法定命令+行政通知混装） | 默认不采集（通知类，量 ~10GB/年）；生效令缺失由 India Code 元数据部分补偿 |
| 公报 Sec 2（法案一读/专委会报告） | 未采集（过程材料，量小 ~265MB/年） |
| 邦级公报（36 邦/联邦属地） | 出界（门户 StateGazette.aspx 有入口） |
| 公报印地语门户（DefaultHindi.aspx） | 未接入（存在性 2026-10-04 实测） |
| 2000–2019 年历史公报 | 门户仅列元数据，电子件无已发现交付通道（2026-10-16 实测；2020 年起全通） |
