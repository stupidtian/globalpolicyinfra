# 俄罗斯（RUS）数据源说明——pravo（官方法律信息互联网门户）

> 数据快照日期：2026-10-12。文中条目计数、字节数与端点形状均为当日对源站直连实测的真实值（可重放复核）。
> 阅读前提：了解 `python cli.py` 用法即可，不需要读代码。俄罗斯全部源总览见 [overview-zh.md](./overview-zh.md)。

## 1. 源概览

### 1.1 制度背景：一个门户、两套系统

俄罗斯联邦层级法律文件的**法定官方公布渠道**是«Официальный интернет-портал правовой информации»（官方法律信息互联网门户，pravo.gov.ru）。其官方公布地位由四个法律文件确立：

| 法律文件 | 管什么 |
|---|---|
| 联邦法 № 5-ФЗ（1994-06-14，经 № 289-ФЗ〔2011-10-21〕等修订） | 联邦宪法性法律、联邦法律、联邦会议两院文件的公布——门户自 2011 年起作为官方电子公布源 |
| 总统令 № 763（1996-05-23） | 总统令、政府决议与指令、联邦行政机关规范性文件的公布 |
| 总统令 № 198（2014-04-02） | 文件在门户上的公布程序 |
| 总统令 № 668（2014-10-14） | 联邦行政机关规范性文件的公布完善 |

在门户上电子公布与纸媒（《俄罗斯报》Российская газета、《联邦法律汇编》Собрание законодательства РФ、《议会报》Парламентская газета）**同等效力**——采门户即获得法定公布全量，无需另抓纸媒。门户是国家法律信息系统（ГСПИ）的组成部分，媒体注册证 Эл № ФС77-47467 签发于 2011-11-10——门户档案起点（见 §7）即此日。

本源实际打交道的有两套系统，同一个**发布号**（номер опубликования）贯穿两者：

| 系统 | 角色 | 交付 |
|---|---|---|
| **publication.pravo.gov.ru**（官方公布） | 枚举（按日检索）+ 文档身份（发布号）+ **扫描原件 PDF**（`/file/pdf` 直链） | 文件交付只有扫描 PDF，无文字层（2026-10-12 普查：抽 19 份联邦件全为扫描件）——身份与原件的来源 |
| **actual.pravo.gov.ru**（官方法律文本库，老检索系统 ips.pravo.gov.ru 的现役继任，测试模式） | 按**同一发布号**取**正文全文**（Word 导出 HTML）+ 版本账 | 只收录进入修订-编纂体系的文件：法律、总统令、政府决议、宪法法院裁决；**部委规章完全不收**（2026-10-12 实测 0/15，跨 2015–2026 各部委）；国际条约与安理会决议也不收 |

本源按文种取数，**两条正文腿由 `content` 参数选择**：

- **`content=html`（默认）**——枚举与身份走公布门户，正文走法律文本库。适用于法律/总统令/政府决议：正文可机读、可清理。
- **`content=pdf`**——正文走公布门户的扫描原件。**部委规章（ведомственные акты，Приказ 等）唯一可用的载体**：2015-01 起上门户（Указ № 668〔2014-10-14〕确立部委文件公布程序），只有影印件没有机读正文；本腿保存法定原件 + 目录数据，时间轴完整、正文不可检索（扫描件的机器识别属另一项工程，见 §8）。

### 1.2 发布号：日期编址的身份证

每份文件有一个全库唯一的发布号，形状为 **`{级代码 4 位}{YYYYMMDD}{当日序号 4 位}`**，共 16 位：

```
0001 2026 10 06 0001
 │    │    │ │  │   └ 当日第 1 份
 │    └────┴─┴──┬── 发布日期 2026-10-06
 └ 联邦级（0001）；联邦主体为 XY00（如 5600 = Оренбургская 州，2026-10-12 实测吻合）
```

联邦级文件一律 `0001` 开头——这是**联邦层与地方层的判别字段**（2026-10-12 各板块实测：总统 19,235 / 政府 58,337 / 91 个活跃部委板块 47,617 / 宪法法院 888 / 国际条约 2,203 / 两院 195，全部 `0001`）。序号不可预测，所以日期编址是"半直构"：**按日枚举**靠公布门户的检索通道，**单份文件**可由发布号直构 URL。

### 1.3 覆盖范围与量级

- **联邦级 ≈ 128,475 份**（上表板块计数合计，2011-11 → 2026-10，2026-10-12 实测）；工作日联邦量 21–57 份/日（2026-10-06 = 57，2026-10-07 = 34，实测）。
- 文种构成（总统板块首 200 条抽样，2026-10-12）：总统令 Указ ≈ 半数、联邦法律 ≈ 三分之一，其余为指令与宪法性法律；部委令（Приказ）在各自板块。
- 三个采集边界（`scope`/`include_court` 参数可放宽，§3）：默认只收联邦级（地方 `XY00` 前缀不采）；默认排除宪法法院裁判（判例）；**国际条约与安理会决议在法律文本库无正文（docid=0，2026-10-12 实测），纯正文口径下不入账**（约 2,400 份，如实记缺）。

## 2. 访问准备

| 项 | 说明 |
|---|---|
| API key | **不需要**，`.env` 无需任何条目 |
| 会话 | 无（无 cookie、无 token；两系统全部请求无状态直连，2026-10-12 连续 100+ 请求实测） |
| 传输 | **纯 HTTP**——443/TLS 从实测网络不可达（对照站正常，属网络路径问题），80 端口全程可用且无强制跳转 |
| 限额/反爬 | 无公开限额，无验证码；robots.txt 全站开放（2026-10-12）。法律文本库为测试系统，偶发传输中断（连接截断/503），框架重试可消化——大量回填时建议温和速率 |
| 响应格式 | 公布门户：服务端渲染 HTML（UTF-8，含大量数字 HTML 实体）；法律文本库：JSON 包裹的 Word 导出 HTML（`{"redtext": "<html…"}`，文件头为 Office 命名空间与 CSS 段，正文在后） |
| 许可 | 公布门户开放数据区明文：自由、免费、无期限、无地域限制的使用（含复制、发布、传播），2026-10-12 实测 |

## 3. 抓什么：任务类型清单

每种任务 = 一次下载 + 一次解析。共 **4 种**（任务链 `pravo_day → pravo_text → pravo_body` 或 `pravo_day → pravo_pdf`，由 `content` 参数选择）：

| 任务类型 | 请求什么 | 产出什么 |
|---|---|---|
| `pravo_day`（种子，逐日一个、逐页派生） | GET 公布门户按日检索（`/search?PublishDateFrom=DD.MM.YYYY&PublishDateTo=DD.MM.YYYY&pageSize=200&index=N`） | 解析目标条目（联邦级 + 文种过滤 + 排除判例）→ 每条按 `content` 派生 `pravo_text` 或 `pravo_pdf`；当日还有下一页 → 派生 `{date, index+1}`；**页尾任务完整消费该日**；窗口终点日的尾页推游标 `pravo_last_date`；当日无文件（«Документы не найдены»，HTTP 200）→ 合法空产出、游标照推 |
| `pravo_text`（html 腿） | GET 法律文本库版本账（`…/api/ebpi/redactions/?bpa=ebpi&t={"pnum":发布号}`） | docid + 全部版本字段入 meta → 派生一个 `pravo_body`；文本库无此文 → 记"未收录"响亮失败（修复通道可日后补抓） |
| `pravo_body`（html 腿） | GET 法律文本库正文（`…/api/ebpi/redtext?bpa=ebpi&t={初始版redid}&ttl=2`） | 验 `{"redtext": "<html…"}` 形状 → 一条文档记录 + HTML 原字节落盘为 `text.html` 主文件 |
| `pravo_pdf`（pdf 腿） | GET 公布门户扫描原件（`/file/pdf?eoNumber={发布号}`） | 验 `%PDF` 魔数 → 一条文档记录 + PDF 原字节落盘为 `doc.pdf` 主文件 |

**逐层过滤**（都在枚举层执行、都随任务参数走，放宽后重跑自动补抓）：`scope`（联邦级 = 发布号前缀 `0001`）/ `include_court`（宪法法院裁判默认排除）/ `types`（文种白名单，如 `types=ORDER` 只收部委规章；空 = 全部）——被过滤掉的条目**不花任何文档请求**。

## 4. 数据落到哪

**零领域表**（同德国 BGBl / 法国 JORF / 西班牙 BOE 路径）：官方公布一份即定、发布号即文档本体，语料内没有跨文档持久实体；版本间的修订关系是**字段**不是实体，随源照收进 meta。一切研究字段进 `documents` 一张表：

| 列 | 内容 |
|---|---|
| `doc_id` | `RUS_{发布日YYYYMMDD}_{hash8(source_url)}` |
| `title` | 完整题名（如 `Указ Президента Российской Федерации от 05.10.2026 № 716 "Об автономной некоммерческой организации…"`） |
| `publication_date` | 官方公布日期——研究时间轴的主日期 |
| `issuing_authority` | 题名内机构短语（Президент Российской Федерации / Правительство Российской Федерации / 具体部委名） |
| `source_url` | `http://publication.pravo.gov.ru/document/{发布号}`——公布门户文档页，身份锚定于此（全年代稳定、可重建） |
| `raw_format` / `language` | `html` / `rus` |
| `doc_type` | 题名文种映射的受控类型（下表）；俄语原词永存 meta |
| `entity_ref` | NULL（扁平国家） |
| `meta` | 见下 |

**meta 字段**（原生字段无损收，全字符串）：`номер`（发布号）、`doc_number`（文号，如 `716`、`369-рп`、`2-ФЗ`，题名内解析）、`doc_date`（签署日期，题名内 «от DD.MM.YYYY»）、`pdf_pages`（公布门户标注页数）、`scope`（federal/all）、`ebpi_docid`（法律文本库内部 id）、`ebpi_versions`（版本账原样串：每版本 `redid@日期/效力状态/修订来源`）、`files`（文件清单）。

**doc_type 映射**（题名文种 → 受控类型；俄语原词永存 meta）：

| 题名开头 | doc_type |
|---|---|
| Федеральный конституционный закон | STATUTE |
| Федеральный закон / Закон Российской Федерации | STATUTE |
| Указ / Распоряжение（Президента） | DECREE |
| Постановление / Распоряжение（Правительства） | DECREE |
| Приказ / Положение（部委令/条例） | ORDER |
| Постановление / Определение（Конституционного Суда，`include_court=yes` 时） | OTHER |
| 其余（Соглашение、Резолюция 等） | OTHER |

文件落点（"一项政策一个文件夹"，年/日双层分片；原始层在本部署位于 E 盘，经目录联接挂在国家目录下）：

```
{数据根}/RUS_policy/
├── state.db · failures/ · 02_cleaned/ · 03_extracted/
└── 01_raw/pravo/                      ← 联接 → E:\RUS_policy\01_raw\pravo
    └── 2026/D20261006/                ← 年 = 发布年；日 = 公布日
        └── 0001202610060001/          ← 发布号命名（全库唯一）
            ├── text.html              ← html 腿：正文 HTML 原样字节（主文件）
            └── doc.pdf                ← pdf 腿：扫描原件原样字节（主文件，二选一）
```

## 5. 完整案例走查（2026-10-06 一份政府决议，源站直连实值 + 账本实值）

1. **按日枚举**：`GET /search?PublishDateFrom=06.10.2026&PublishDateTo=06.10.2026&pageSize=200` → 200。当日全级 525 条（含地方）、联邦级 57 条；第 54 号条目 `0001202610060054`——题名 `Постановление Правительства Российской Федерации от 05.10.2026 № 1297 "О внесении изменени…"`，公布日 06.10.2026。
2. **版本账**：`GET …/redactions/?bpa=ebpi&t={"pnum":"0001202610060054"}` → docid 与版本列表（含刊出原样版标记）入 meta。
3. **正文取回**：`GET …/redtext?bpa=ebpi&t={初始版redid}&ttl=2` → `{"redtext": "<!DOCTYPE html>…"}`，**853,129 字节** Word 导出 HTML（库内最大件）。
4. **入账落盘**：文件夹 `01_raw/pravo/2026/D20261006/0001202610060054/text.html`；documents 一行 `RUS_20261006_eaa6f7b5`（doc_id 以公布日与文档页 URL 计算；doc_type DECREE、机构 Правительство Российской Федерации）。
5. **三方对账（2026-10-12 实测，最大件逐字节）**：磁盘文件 sha256 ≡ 账本 file_hash ≡ 源站复取原字节，41/41 份磁盘≡账本（哈希+字节数）全一致；同窗口重复运行**零新任务、零请求**。
6. **窗口合计**（2026-10-05..07 三日实跑）：3 日种子 + 7 枚举页任务、联邦条目 107（判例/地方已滤），41 份入账（公布 10-05 = 7 份、10-06 = 14 份、10-07 = 20 份；文件 21.9KB..853KB）、66 份“法律文本库未收录”响亮记档（抽查定性：新部委令登记滞后 + 条约不收录——`requeue` 日后补抓）；正文提取 41/41（346..410,151 字符，均值 17,872），最小件开头 `ПРАВИТЕЛЬСТВО РОССИЙСКОЙ ФЕДЕРАЦИИ / РАСПОРЯЖЕНИЕ / от 5 октября 2026 г. № 2778-р…`。

## 6. 怎么跑

```bash
# 演练（不入队执行，看会抓什么）
python cli.py collect --country rus --source pravo window=2026-10-05:2026-10-07 --dry-run

# 小窗口真实抓取
python cli.py collect --country rus --source pravo window=2026-10-05:2026-10-07

# 每日增量（从上次游标的次日追到昨天）
python cli.py collect --country rus --source pravo sync=1

# 放宽采集范围（示例：连地方一起收 / 连宪法法院裁判一起收）
python cli.py collect --country rus --source pravo window=… scope=all
python cli.py collect --country rus --source pravo window=… include_court=yes

# 文种过滤 + 载体选择（部委规章只有扫描件，走 pdf 腿）
python cli.py collect --country rus --source pravo window=2015-01-01:2015-12-31 types=ORDER content=pdf

# 正文提取（清理）
python cli.py clean --country rus --dry-run
python cli.py clean --country rus --limit 500

# 状态 / 快照 / 修复
python cli.py status --country rus --source pravo
python cli.py export --country rus
python cli.py requeue --country rus        # 补抓“法律文本库未收录”（新件登记滞后自愈）
```

## 7. 更新与增量

- **游标**：`pravo_last_date`。一个 `pravo_day` 链（该日全部检索页）完整消费才把游标推到该日——中途崩溃该日不推，下次自愈；空日与历史空档日照推（检索通道对"当日无文件"给出确定回答）。
- **sync 终点取昨天、不取今天**：当日文件在莫斯科工作时段内分批上刊，"尚未生成"与"当日无刊"不可分形，故增量默认只到昨天。
- **新件登记滞后（本源特有的时差）**：文件在公布门户出现后，进入法律文本库通常要等司法部登记（实测 1 份公布 3 天后的部委令尚未入行）。因此**近日窗口会有一批“法律文本库未收录”**——它们响亮记档，跑 `python cli.py requeue --country rus` 即补抓；建议每周补抓一次。已入账文件不会被重复抓（任务确定性跳过）。
- 同窗口重复运行幂等零请求；往更早日期回填会把游标往回带，下次 sync 幂等重扫（无害）。
- 2011-11-10 之前的日期检索为空——那是档案起点，不是故障。

## 8. 已知边界与缺口

| 缺口 | 说明 |
|---|---|
| **部委规章无机读正文（全年代）** | 法律文本库不收该类（2026-10-12 实测 0/15，机制 = 部委规章不进修订-编纂体系）；门户只有扫描 PDF。`content=pdf` 腿保存法定原件 + 目录时间轴；正文识别需扫描件机器读取——架构上限定走专门的网络解析服务（配额按页计，俄语质量待验证），是独立工程 |
| **部委规章上门户的起点是 2015-01** | Указ № 668（2014-10-14）确立部委文件公布程序；三个部委板块最老文档实测均为 2015 年 1 月。2015 年之前该类不存在机读目录 |
| **国际条约与安理会决议无正文** | 法律文本库不收录（2026-10-12 实测 docid=0），html 腿下不入账（约 2,400 份）。需要这批文件走 `content=pdf` 腿 |
| **新件登记滞后（html 腿）** | 文件在公布门户出现后，进入法律文本库通常要等司法部登记（实测 1 份公布 3 天后的部委令不在库；法令类的滞后更短）——`requeue` 补抓自愈，建议每周一轮 |
| **个别历史缺档（html 腿）** | 2017 年抽样 5 份中 2 份不在文本库（2026-10-12）——同走 `requeue` 通道，长期缺档如实存在 |
| **正文是 Word 导出 HTML** | 文件头含 Office 命名空间与 CSS 段（22KB 文件中正文约占半）；正文提取（clean）已按此形状配置 |
| **法律文本库是测试模式系统** | API 无官方文档（接口形状 2026-10-12 从官方前端脚本逆出并实测固化）；实测偶发传输中断，重试可消化；系统若下线，身份与枚举不受影响（锚定公布门户），补内容可另走扫描 PDF |
| **只收联邦级** | 地方（`XY00` 前缀）与宪法法院裁判默认不采；`scope=all` / `include_court=yes` 可放宽 |
| **生效日期原生无** | 公布门户与法律文本库都不给生效日——时间轴以公布日为主、签署日随 meta；生效日缺省如实记档 |
| **档案早年稀疏** | 2011-11 起收录、2012 年初前多日为空（实测 2011-11-15 全级 0 条）——源数据现实，枚举自然消化 |
| **扫描 PDF 腿不清理** | `clean` 只服务 html 腿（pdf 腿是无文字层扫描件，几何提取必空——清理声明不覆盖 `pravo_pdf`，不会产生无意义的失败任务） |

## 9. 端点速查表

**在用**：

| 用途 | URL 模式 |
|---|---|
| 按日检索（枚举唯一入口） | `GET http://publication.pravo.gov.ru/search?PublishDateFrom=DD.MM.YYYY&PublishDateTo=DD.MM.YYYY&pageSize=200&index=N` |
