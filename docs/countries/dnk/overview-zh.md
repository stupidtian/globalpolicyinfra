## 1b. 三结构现状

- **时间序列（必答）**：retsinformation 公报层承担——Lovtidende A/B 的全部公布事件，公布日、签署日结构化齐全（生效日站内无结构化字段、如实记缺）；近期经检索通道按日增量，2024-04 前经 sitemap 回填入口。
- **决策过程**：记缺——议会过程（提案、宣读、表决）在 Folketinget 议会系统与站内 `/eli/ft/` 文件流，未采集（源文档已记边界）。
- **版本序列**：retsinformation 承担——站内为每部法维护原生版本时间线（主法 + 历次修订法 + 历代整合版），`laws` 表一行一法 + timeline.json 落盘，现行指针随抓取刷新；丹麦的整合方式是重新公布（LBK 本身即公报事件），两层天然咬合。

## 2. 共享访问准备

- 无需 API key；`.env` 零条目。许可：国家行政署开放数据条款（免费、非独占、无限制再利用；法律文本无版权，引用注明来源即可）。
- **反爬提示**：www.retsinformation.dk 有 Cloudflare，按 TLS 指纹拦截 curl 及同类命令行工具（403）——用标准 HTTP 库（框架传输层原生兼容）。
- 限速节奏：普通采集用框架默认（`--delay 0.5:1.5` 足够安全，实测连续约 200 请求零拦截）；**收割 API 例外**——每 10 秒 1 次（超过即 429），刷新清扫必须 `--delay 10:12`。
- 数据目录即框架标准布局：`{data_root}/DNK_policy/`，`state.db` 账本 + `01_raw/retsinformation/` 原始层。
